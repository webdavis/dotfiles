# Finding normalization boundary

The domain owns detector admission, pack-prefix removal, baseline exemptions, renameio suppression, and
enrichment-path selection and sanitation. It takes typed facts and borrowed paths. Parsing, action and
column defaults, and the four-field record belong to the results-log adapter in plan row 3.1. This
follows step 2's explicit pure-policy boundary and keeps serialization out of the domain.

The captured renameio predicate applies to every admitted detector carrying a matching `target_path`,
including `new_admin_user`. The port retains that behavior. The Bash comment and specification mention
only file events, which is narrower than the actual predicate. An empty system-extension bundle path also
remains empty; only an absent value selects the fallback path.

The twelve original normalizer tests remain active. Their name mapping records each domain successor and
each codec contract that row 3.1 must preserve. S031 already has a named snapshot test. S022's new Bash
acceptance example pins failure propagation for the later stream adapter and cursor owner.

Codec investigation found two constraints for row 3.1: valid numbers can exceed floating-point range, and
opaque columns can exceed serde_json's default nesting limit. Raw-value forwarding changes jq's
duplicate-key and escape normalization, while disabling the recursion limit alone leaves recursive
operations vulnerable to stack overflow. Row 2.1 adds no codec, dependency, depth limit or caller change.
