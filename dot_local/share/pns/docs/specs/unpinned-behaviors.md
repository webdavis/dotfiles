# Behaviors this crate specifies that no test currently pins

Every row below names a behavior described in `docs/specs/` that, as far as the specification writing
could establish, no test pins. The list exists to serve one rule from the refactoring program: before a
later pull request MOVES the code behind one of these, it writes the missing test FIRST, against the code
in its current location, and lands that test before the move. A move's only honest evidence is that it
changed nothing, and a behavior with no test that can fail has no such evidence.

## What this list is, and what it is not

It is derived from the `NOT ESTABLISHED:` lines the specifications record, split into two kinds:

- **Test gap.** The behavior is understood and nothing pins it. These are the rows that block a move.
- **Open question.** The code does not settle the question, so there is nothing to pin yet. Answer the
  question first, then decide whether it needs a test.

**It is not a proof of completeness.** It records the gaps the specification writing NOTICED while
reading the source and the tests. A behavior can be unpinned without anyone noticing it, and the only
reliable check for that is the one the program already requires per behavior: mutate the source the test
covers and prove a test goes red, against an unmutated control at the same relative depth. Treat this
list as the known minimum and run that check before every move, whether or not the behavior appears
here.

Two entries are findings rather than merely missing tests, and are called out because a test alone will
not close them:

- An executable channel runs with **no deadline and no output ceiling**. `src/main.rs:deliver` spawns the
  channel and calls `child.wait()`, so a wedged channel holds the event open indefinitely. Every other
  delivery path and every probe is bounded.
- **Nothing calls `fsync`, `sync_all` or `sync_data` anywhere in the crate**, so there is no durability
  guarantee to test. That is a decision the persistence step has to take deliberately rather than
  inherit.
